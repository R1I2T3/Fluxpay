Oracle integration verification

A separate FLUXPAY_TEST schema was used to avoid altering application data. Flyway applied the full migration history through V502. The integration test created a unique user and KYC application through the HTTP layer, verified persistence via repositories, then removed transient data after execution.

Repeat command: Set ORACLE_TEST_JDBC_URL, ORACLE_TEST_USERNAME and ORACLE_TEST_PASSWORD for the dedicated test schema, then run .\mvnw.cmd -f backend\pom.xml test. The backend server does not need to be running.

5. Issues found and resolved

The following issues were identified during test preparation or execution. Each was corrected and retested.

IDIssue foundResolutionVerification
T-01Padded/mixed-case email login failed request validation before canonicalization.Removed strict email-format validation from LoginRequest; retained required/length validation so AuthService can trim and lowercase legacy input.Postman padded/mixed-case login returned 200.
T-02Authenticated admin requests initially returned AUTH_REQUIRED while testing rejection.Corrected request route to /api/admin/kyc/applications/{id}/reject. JWT filter registration was also made explicit in the security chain.Blank reason returned 400; valid reject returned 200.
T-03Oracle test migration failed because test schema lacked identity/sequence privileges.Recreated FLUXPAY_TEST with quota and CREATE SESSION, TABLE, TRIGGER, and SEQUENCE privileges.Flyway to V502 and Oracle integration test passed.
T-04Initial Oracle privilege script included CREATE INDEX, which was invalid in this grant context.Removed invalid privilege; granted only required valid privileges.Test-user setup completed successfully.

Known non-blocking observation

Flyway emitted a compatibility warning because local Oracle is newer than the latest explicitly supported version in the bundled Flyway release. It did not prevent migrations or tests: V502 and all integration checks completed successfully. Review this during dependency maintenance; it is not a current test failure.

The backend is ready for the next project phase, with FLUXPAY_TEST retained for repeatable integration testing.
